## 一、AI 的层级关系

### 问 1：AI、机器学习、深度学习、大模型是什么关系？

是**嵌套包含**关系，一层套一层：

```
AI（最大的圈 —— 一门学科）
  └─ 机器学习（AI 的一种方法 —— 从数据中自动学出规则）
       └─ 深度学习（机器学习的一种 —— 用多层神经网络来学习）
            └─ 大模型（深度学习的产物 —— 参数量巨大的模型）
```

**类比前端**：

```
编程（学科）
  └─ 前端开发（一种开发方向）
       └─ Vue 框架（一种具体技术）
            └─ Vue 3 + Composition API（一种具体实现）
```

---

### 问 2：机器学习和传统编程有什么区别？

核心区别在于**谁来写规则**：

| | 传统编程 | 机器学习 |
|---|---|---|
| 输入 | 数据 + **人写的规则** | 数据 + **标注（正确答案）** |
| 输出 | 结果 | **机器学出的规则** |

**具体例子**：判断照片里是猫还是狗

- 传统编程：你写规则 —— "尖耳朵+竖瞳孔=猫，垂耳朵+圆瞳孔=狗"（规则写不完，总有例外）
- 机器学习：你给机器 1000 张标注好"猫"或"狗"的照片，机器自己学出判断规则

**程序员的工作从"写规则"变成了"准备数据和标注"。**

**类比前端**：传统编程像手写 CSS，机器学习像 Tailwind CSS —— 你只需要给 class 名（标注），样式（规则）自动生成。

### 问 3：什么是深度学习？"深"在哪里？

深度学习使用**多层神经网络**来学习。"深"指的是**层数多**（几十层到上千层）。

每一层对数据做一次变换，逐步提取越来越抽象的特征：

| 层级 | 做什么（以图像识别为例） |
|------|------------------------|
| 第 1 层 | 识别边缘、线条（"这里有一条弯线"） |
| 第 2 层 | 把边缘组合成形状（"这个形状像耳朵"） |
| 第 3 层 | 把形状组合成部件（"这是猫脸的一部分"） |
| 最后一层 | 综合判断（"这是一只猫"） |

**类比前端**：就像 Vue 组件的嵌套 —— 每一层组件处理不同层级的逻辑，层层传递，最后渲染出完整的 UI。

### 问 4：为什么叫"大"模型？"大"指什么？

"大"指的是**参数量巨大**。

参数就是机器从数据中学出来的规则。每一个参数是一个小小的"判断规则"：

- 简单模型：几千个参数
- GPT-3：**1750 亿**个参数
- GPT-4：据传**万亿级**参数

参数越多，模型能学到的模式就越复杂，能力就越强。

**类比前端**：就像一个配置对象 —— 配置项越多，能控制的行为就越精细。只不过大模型的"配置项"是机器自己学出来的，不是人写的。

## 二、主流大模型家族

### 问 5：主流大模型有哪些？

差异主要体现在两个维度：

**维度一：能力方向**

| 模型 | 背后的公司 | 特点 |
|------|-----------|------|
| GPT 系列 | OpenAI（美国） | 综合能力强，生态最成熟 |
| Claude | Anthropic（美国） | 长文本处理、代码、推理能力强 |
| Gemini | Google（美国） | 多模态原生支持，搜索集成 |
| 通义千问（Qwen） | 阿里巴巴（中国） | 中文能力强，有开源版本 |
| GLM | 智谱 AI（中国） | 中文理解好，学术背景深 |
| 豆包 | 字节跳动（中国） | 多模态，中文场景优化 |

**维度二：开源 vs 闭源**

| | 开源模型 | 闭源模型 |
|---|---|---|
| 使用方式 | 下载后本地部署 | 通过 API 调用 |
| 成本 | 硬件成本（GPU） | 按量付费（Token 计费） |
| 数据隐私 | 数据不出本地 | 数据经过第三方服务器 |
| 定制能力 | 可以微调、修改 | 只能在 Prompt 层面调整 |

**类比前端**：开源模型像 Vue/React（代码公开，自由使用），闭源模型像某些商业 UI 组件库（付费使用，功能完善但不可修改）。

## 三、大模型能做什么

### 问 6：除了聊天，大模型有哪些实际应用场景？

| 类别 | 例子 |
|------|------|
| 对话与问答 | 聊天机器人、客服系统、知识问答 |
| 内容生成 | 文档、邮件、营销文案、翻译 |
| 代码辅助 | 写代码、Code Review、Debug、生成测试 |
| 多模态 | 生成图片、视频、语音识别 |
| 数据分析 | 从报表中提取洞察、生成图表 |
| RAG（检索增强） | 基于私有文档的问答系统 |
| Agent（智能体） | 让 AI 调用工具完成复杂任务 |

## 四、RAG：检索增强生成

### 问 7：什么是 RAG？

大模型的训练数据里没有公司内部文档，怎么让它基于这些文档回答问题？

RAG 的思路是 —— 不改模型，每次提问时先**搜出相关文档片段**，拼进 Prompt 里给模型看。

```
用户提问 → 搜索相关文档 → 把文档片段 + 问题一起发给模型 → 模型基于文档内容回答
```

**类比前端**：就像考试时翻书找答案 —— 你不需要把所有书背下来（微调），只需要知道怎么快速找到相关内容（检索），然后理解并作答（生成）。

**为什么不直接微调模型？**
- 微调成本高、周期长
- 文档更新后需要重新微调
- RAG 只需要更新文档库，成本低、更新快

## 五、Agent：智能体

### 问 8：什么是 Agent？

让 AI 帮忙订机票，它需要查航班、比价格、下单。大模型本身不能操作网站，怎么办？

Agent（智能体）就是让大模型能**调用外部工具**来完成任务。

```
用户："帮我订明天去上海的机票"
  → 模型思考：需要查航班（调用航班查询工具）
  → 模型思考：需要比价格（调用价格比较工具）
  → 模型思考：需要下单（调用下单工具）
  → 返回结果
```

**类比前端**：普通对话像静态页面（只能展示），Agent 像 SPA 应用（能交互、能调 API、能操作状态）。Agent = 大模型 + 工具调用能力。

## 关键概念速查

| 概念 | 一句话解释 | 类比前端 |
|------|-----------|---------|
| Token | 模型处理文本的最小单位 | HTTP 请求的 payload 大小 |
| 上下文窗口 | 模型一次能"看到"的最大文本长度 | 浏览器的 history 栈大小限制 |
| 幻觉 | 模型一本正经地编造不存在的信息 | 前端表单校验不能替代后端校验 |
| 对齐（Alignment） | 让模型的输出符合人类期望和价值观 | UI 设计规范 |
| Embedding | 把文本变成一串数字（向量），方便计算机比较相似性 | 把设计稿转成组件代码的"特征码" |
| Prompt | 给模型的输入/指令 | API 请求的参数 |
| Fine-tuning | 用特定数据重新训练模型 | 用 mixin/插件扩展组件行为 |

---

## 关键要点总结

1. **AI > 机器学习 > 深度学习 > 大模型**，是嵌套包含关系
2. **机器学习的核心**：从数据中自动学出规则（替代人写规则）
3. **深度学习的"深"**：神经网络层数多，每层提取不同层级的特征
4. **大模型的"大"**：参数量巨大（百亿到万亿级）
5. **核心应用**：对话、生成、代码、多模态、RAG（检索增强）、Agent（工具调用）
6. **RAG** = 检索 + 生成，不改模型，让模型"翻书找答案"
7. **Agent** = 大模型 + 工具调用，让 AI 能"行动"而不只是"回答"
